# GNOME performance optimization — 2026-10-09

Installed five targeted extension source changes while retaining all 19 enabled
extensions, existing appearance, rounded shadows, and approved animation behavior.
The source changes require logout/login. No applications were terminated and no
system/kernel configuration or hardware-project files were edited.

## Changes

- Blur My Shell: initialize folder blur before first popup instead of eagerly
  constructing every folder dialog on app-grid load. Native popup/fade behavior,
  radius and brightness are preserved; the popup hook is restored on disable.
- App Grid Tuner: retain lazy native folder creation, apply styles before the first
  popup, and cache unchanged folder configuration/app IDs to avoid repeated
  redisplay. Restore per-folder method wrappers on removal/disable.
- RunCat: pause sprite timers while the actor is unmapped and resume the same
  smoothed ticker on mapping. Late CPU-query callbacks ignore destroyed actors.
  Visible sprite speed, smoothing, frame sequence and polling interval are unchanged.
- System Monitor: stop one-second section polls while the parent indicator is
  unmapped; resume immediately on mapping. Network counter deltas use the actual
  elapsed interval, so hidden time does not produce an artificial rate spike.
- Vitals: avoid unused absolute-value categories, CPU-frequency files, wireless
  metadata and filesystem-usage work while its menu is closed. Keep CPU/storage
  counter baselines and network history warm. Pinned sensors still update at the
  original interval and opening the menu queries every enabled category.
- Just Perfection: change `animation` from 5 (0.8x duration) to 1 (native duration),
  matching the user's requested normal Overview opening speed.
- Previously installed Rounded Corners Light revision 5 remains unchanged. It
  reuses cached source-window masks rather than resizing an offscreen preview
  texture every animation frame. The running Shell still reports revision 4.

An experimental panel-blur repaint change did not demonstrate a clear benefit and
was discarded. Dynamic blur, its shadow-artifact workaround, sigma, brightness,
theme styles, switcher layouts and refresh rate were not reduced.

## Verification

Private GNOME Shell 50.5 Wayland compositor, 2560x1440 at 165 Hz, six 1600x1000
Wayland CSD fixtures. Eighteen actual extensions were ACTIVE together, with no
extension initialization errors; GSConnect was excluded to avoid starting network
device coordination in a second session. Clipboard history and device identities
were not copied into the test. All comparisons below use native animation factor 1
and the balanced power profile.

| Variant | Paint CPU median / p95 (ms) | Paint interval median / p95 (ms) |
| --- | --- | --- |
| Extensions disabled | 0.854 / 1.448 | 6.040 / 6.555 |
| Original extensions + cached rounded revision 4 | 6.379 / 23.325 | 8.343 / 26.084 |
| Optimized extensions + rounded revision 5 | 1.534 / 2.296 | 5.995 / 6.672 |

These are headless paint timings, not physical display FPS. Samples are affected
by concurrently running real applications. The comparison to revision 4 includes
the rounded-extension optimization from the preceding task; the five additional
changes alone did not demonstrate a large further improvement in steady-state
Overview paint cost. They reduce unnecessary work, especially hidden polling,
unopened folders and repeated grid updates. No claim of zero lag or performance
better than disabling all extensions is supported.

The final optimized run passed 28 functional checks: mapping/timer pause/resume,
folder creation/opening, blur attachment and cleanup, configuration caching,
sensor categories, retained rate baselines, actual sensor-file filtering, menu
usability (126 sensor items), and re-enable/disable lifecycle. Ten unopened folder
dialogs became zero until used; actual closed-menu sensor reads fell from 39 to
31 in the controlled GPU-stubbed sensor probe. All five installed source files
match the tested copies byte-for-byte and pass `node --check`.

Existing native/third-party warnings also occurred in the original stack, including
zero-width framebuffers/workspace thumbnails and GC teardown callbacks. Their
presence is not evidence that all desktop interactions are fixed. Native physical
pointer, gestures, device integration, and a full real post-login session remain
to be verified; desktop-control tools were unavailable in this turn.

## Power and thermal results

The user initially selected performance on AC and balanced on battery. A small
event-driven user service was prepared and tested, then native Performance was
activated on AC. CPU package temperature reached 97 C during measurements. The
profile was immediately returned to balanced. The user subsequently explicitly
selected balanced all the time. The service was stopped, disabled and removed;
its source/unit remain recoverable as `rejected-power-policy.*` in this folder.
Balanced is the verified final active profile, with governor `powersave`, EPP
`balance_performance`, and Intel minimum performance percentage 10.

Thermal peaks also occurred under the later private benchmark on balanced, so
the spike cannot be attributed solely to the performance profile. Software
extension tuning does not establish that cooling is sufficient under every load.
At initial idle inspection there was no sustained CPU, memory or swap pressure;
therefore no arbitrary swap, cache, background-service or process-killing changes
were applied.

5, Enabled Yes, State ACTIVE. Then check real Overview entry/exit, app folders,
panel menus, hidden/fullscreen indicators, corner resizing and Alt+Tab. The native
animation setting and balanced profile are already applied live.

`python3 restore.py` previews restoration; `python3 restore.py --apply` restores
only the five files whose hashes still match these patches, and restores the
earlier animation setting only if it has not been changed again. It does not
alter the balanced power selection or the preceding rounded revision-5 work.
Backups are under `before/`; test evidence and harness are under `validation/`.
Future third-party extension updates may replace local source patches.
